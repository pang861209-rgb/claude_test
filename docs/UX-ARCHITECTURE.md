# 약먹핑 UX 아키텍처 리뷰 (v1)

> 시니어 UX 관점 점검. 대상: P0 구현 완료 시점. 상세 버전은 아티팩트 문서 참조.

## 1. 유저 프로파일

**주 사용자 (아내)**: 하루 2회 복약, 깜박/미룸 패턴. 알람은 끄면 끝. 귀여운 캐릭터·핑크 감성 선호. 복잡한 UI는 이탈 요인.
**보조 사용자 (남편)**: 기록 확인. "먹었어?" 잔소리 루프를 캘린더 확인으로 대체하는 것이 숨은 목표.

### 행동 인사이트 → 설계 원칙

| 관찰 | 원칙 | 현재 |
|---|---|---|
| 알람 끄고 안 먹음 | 해제 비용 > 무시 비용 (인증만이 알림을 멈춤) | ✅ |
| 혼나면 앱 삭제 | 질책 제로 | ✅ |
| 귀찮으면 안 함 | 3탭 원칙 (알림→카메라→완료) | ✅ |
| 즉각 보상에 반응 | 가변 보상 (랜덤 칭찬+파티클+햅틱) | ✅ |
| 생활은 계획대로 안 흘러감 | 예외 흡수 (조기/지연/자정) | ❌ 갭 |
| 첫 팝업은 일단 거부 | 권한 프라이밍 | ❌ 갭 |

## 2. 구조 평가

- 탭 3개(홈/캘린더/설정) + 카메라·축하는 오버레이 → **적절, 유지**
- 홈 = "지금 해야 할 한 가지"에 집중 → **적절**
- 코어 루프의 약한 고리: 알림 12회(1시간) 후 침묵

## 3. 슬롯 상태 머신 (제안 포함)

현재: `disabled / waiting / dueNow / completed`
제안: + `soon` (T−2h부터 조기 인증 가능), + `missed` (자정 경과 명시화)

## 4. 갭 분석

| 심각도 | 항목 | 요지 |
|---|---|---|
| HIGH | 온보딩·권한 프라이밍 부재 | 첫 실행 즉시 시스템 팝업 → 거부 시 회복 비용 큼. 3장 온보딩 + 프라이밍 후 요청 |
| HIGH | 자정 넘김 귀속 미구현 (기획 §10) | 새벽 인증이 다음 날짜로 기록됨. 직전 저녁 슬롯 귀속 분기 필요 |
| HIGH | 조기 복용 기록 불가 | 시간 전 인증 버튼 없음 → `soon` 상태 도입 |
| MID | 1시간 후 알림 침묵 | +1.5h/+2h/+3h 희소 후속 알림 3개 추가 |
| MID | 축하 2초 고정 | 2.5~3s + 탭 스킵 + 마스코트 등장 |
| MID | Dynamic Type 미지원 | 폰트 헬퍼 relativeTo 전환 |
| LOW | 앱 아이콘 / 알림 화자 톤 / 시뮬레이터 앨범 폴백 / 위젯(P1) | 폴리싱 |

## 5. 판정 & 로드맵

**방향성: 맞음.** 핵심 축(해제 비용 설계·질책 제로·즉시 보상)은 유저에 정확히 부합. 리스크는 기능 부족이 아니라 **현실의 예외에서 루프가 끊기는 것**.

- **P0.5 (다음 스프린트)**: ① 온보딩+프라이밍 ② 자정 귀속 수정 ③ 조기 인증 ④ 후속 알림 ⑤ 축하 개선
- **P1**: 잠금화면 위젯 → 앱 아이콘 → 지연 완료 뱃지 → Dynamic Type → 커스텀 사운드
